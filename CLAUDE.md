# Second Brain — Map

This file is the index for a flat-Markdown "second brain": a personal knowledge base of plain `.md` files organized into semantic folders. No app, no database — just files on disk and this map telling the agent where to look.

@MEMORY.md
@decisions.md

## Folders

-   `notes/` — Facts and topic-specific entries. One file per topic (e.g. `notes/tax-policy.md`).
-   `people/` — Cards for contacts or companies: who they are, meeting summaries, key details. One file per person or org (e.g. `people/ivan-petrov.md`).
-   `projects/` — Project status: what's being worked on, where it was paused, and the next steps. One file per project (e.g. `projects/second-brain-setup.md`).

## Root files

-   `MEMORY.md` — Long-term, core info that should always stay in context.
-   `LEARNINGS.md` — Lessons learned, worth revisiting before repeating a mistake.
-   `decisions.md` — Audit log of decisions made and why.

## Naming rules

1. **One file = one topic.** Never dump unrelated points into a single catch-all file. If it's about "Tax Policy," it lives in `tax-policy.md`, not folded into `notes.md`.
2. **Topic as name.** Name the file for what it contains: `ivan-petrov.md`, not `note-12.md`.
3. **Unified style.** Lowercase and hyphens only, e.g. `second-brain-setup.md`.

## How to read this

When answering a question, use this map to find the right file(s) under `notes/`, `people/`, or `projects/`, read them, and cite the file you drew from. If the answer isn't in any file here, say so rather than guessing.

When adding new knowledge, write it into the correct folder under the naming rules above instead of appending to an unrelated file. Only add a new top-level folder here once a topic grows large enough to need its own directory — start with these three.
